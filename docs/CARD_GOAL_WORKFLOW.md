# 카드뉴스 완성까지 이어지는 처리 — 2026-09-22

사용자는 자료를 추가하고, 필요한 경우 본문을 보충한 뒤, 완성된 이미지·캡션·출처를 받는다. 새 소식의 ‘이 소식으로 카드뉴스 만들기’와 기존 자료의 ‘8장 카드뉴스 만들기’도 같은 목표에 연결된다. 기존 분석은 보존한다. 2026-09-22 사용자의 전체 제작 요청으로 활성 자료 59건을 v2 기준으로 예약했다. 기존 완성 이미지도 이전 실행에 보존된다.

## 제작 한도와 보기

- 직접 제작·재개 요청은 앱의 일일 한도가 없다. 자동 수집과 일일 소식에서 오는 요청에는 `automatic`, 사용자 요청에는 `manual` 출처를 서버에서 지정한다.
- 자동 제작은 한국 시간 하루 최대 3건, 각 8장이다. 큐에 넣은 날짜가 아니라 실제 처리 시작 날짜에 DB에서 3개 슬롯을 예약한다. 같은 실행의 재시도는 중복 차감하지 않고, 다른 실행은 같은 자료라도 별도로 계산한다. 실패한 시도도 당일 슬롯을 유지해 반복 요청으로 한도가 풀리지 않는다.
- 초과한 자동 요청은 다음 한국 날짜 자정 이후로 미룬다. 수동 요청으로 재개하면 자동 한도와 분리한다. 수동 대기열은 자동 수집의 일반 큐 한도를 소모하지 않는다.
- 기본 이미지는 1080×1350 개별 PNG다. 좌우 버튼·점 선택·방향키/Home/End·터치/트랙패드 스크롤로 한 장씩 본다. 자동 넘김은 없고, 움직임 최소화 설정을 따른다. 이미지별 PNG와 전체 ZIP을 받을 수 있다.
- 자동 수집 예약과 실제 제작은 별개다. 처리 PC가 켜져 있고 프로바이더가 연결돼 있어야 대기열이 진행된다. 앱 한도와 외부 AI 제공자의 이용 제한은 별개다.

## 실행 상태와 연결

`source → analysis → story → render → verify → done`

- 상태: queued, running, recovering, waiting_input, failed, completed.
- 원문 확보 실패: 읽은 척하거나 요약문을 전체 원문으로 쓰지 않는다. 본문 추가 행동을 안내한다.
- 원고 검수 실패: 정확한 검수 사유를 전달해 story를 수정한다.
- 이미지 배치 실패: 먼저 여백·글자 크기를 두 번 조정한다. 실제 본문 안전 영역과 하단 조건을 분리해 검수하며, 여전히 넘칠 때 story로 돌아가 문제 장을 수정한다.
- 저장 이미지 손상·누락: render로 돌아간다.
- 일시적 연결 실패: 완료한 단계는 보존하고 제한된 횟수만 재시도한다.
- 각 단계 최대 3회. 처리 프로세스 중단은 기존 큐의 최대 3회 재수령과 lease로 복구한다. 한도에 도달하면 실패 상태와 사용자의 재개 버튼을 제공한다.
- 단계별 내용과 개별 이미지 저장을 체크포인트로 보존한다. 원문이 바뀌면 새 버전으로 생성하며 오래된 결과를 새 결과로 배포하지 않는다.
- 큐·원문 소유자, 현재 lease, revision, 원문 hash를 검증한 RPC만 체크포인트를 변경한다. 종료된 실행의 늦은 결과는 저장하지 않는다.

## 완료 기준

기본 8장(3~12장 설정)의 개별 PNG, 각각 1080×1350, 저장 후 해시·포맷·크기 검증, 원문 인용·수치·중복·구도·길이 확인, AI 편집 검수, 캡션과 출처가 모두 있어야 completed다. 글꼴은 로컬 Noto Sans KR(OFL)이며 외부 글꼴 요청에 의존하지 않는다. ZIP에는 장별 PNG와 caption.txt, sources.txt, image-prompts.txt, storyboard.json을 제공한다.

현재 자동 출력은 Satori와 Sharp로 만드는 편집형 이미지다. 외부 사진·콜라주 생성 모델은 연결되어 있지 않다. 사진 생성 모델용 독립 프롬프트를 별도로 제공하며 모델을 실제로 호출했다고 표시하지 않는다. 인터넷 검색을 통한 최신 사실의 독립 검증은 수행하지 않으므로 원문 기준이라는 한계를 표시한다. 자동 검수는 사람의 최종 교정을 대체하는 보증이 아니다.

## 운영 학습

개인 소유자·프롬프트 버전·실패 단계·오류 분류·출처 호스트로 오류 패턴을 구분한다. 실패와 해결 이력은 ai_atlas_card_events에, 검증된 해결 방법의 성공·실패 횟수는 ai_atlas_recovery_rules에 남긴다. 원문 추가나 문구 수정 후 실패 단계가 실제 통과했을 때만 성공으로 집계한다.

긴 항목으로 배치가 실패했다가 항목 축약으로 해결된 패턴은 다음 원고 생성에 예방 지침으로 넣는다. 실패가 많아진 방법은 검증된 방법으로 취급하지 않는다. 실행 가능한 조치는 코드의 고정된 허용 목록에 한정한다. 모델 가중치 학습, 임의 코드 수정, 보안 제한 우회가 아니다.

## 설치와 접근 경계

- 적용할 마이그레이션: `20260922023826_card_goal_workflows.sql`, `20260922030330_card_goal_queue_failure_sync.sql`, `20260922051137_card_creation_policy.sql`.
- `node --env-file=.env.local --import tsx scripts/setup-card-storage.ts`로 비공개 `ai-atlas-cards` 버킷을 준비한다.
- 신규 세 테이블은 RLS와 소유자별 조회 정책을 사용하며 클라이언트 변경 권한을 주지 않는다. 버킷에는 클라이언트 직접 접근 정책이 없고 서버의 인증·허용 계정·소유자 검사 후 PNG/ZIP을 제공한다.
- 처리 PC는 기존 outbound worker를 사용한다. 인바운드 포트나 공개 파일 URL을 추가하지 않는다. 프로바이더는 기존 Hermes/Ollama 설정이며 유료 API로 자동 전환하지 않는다.
