## 실제로 확인한 실패 원인

1. **원문 인용을 다시 쓴 생성 결과**: 첫 실패를 수정 전 코드로 실제 Ollama에서 한 번 재현했다. HTTP 200, done/stop 정상, 입력 1,496 / 출력 3,965 토큰, 문단 6개와 카드 6개였지만 인용 6개 중 5개가 실제 원문과 불일치했다. 문단 인덱스는 모두 유효했다. 연결 장애가 아니었다. 나머지 두 자료는 저장된 동일 인용/문단 연결 오류와 analysis 3회 실패를 확인했으며 불필요한 재현 호출을 추가하지 않았다.
2. **오류 오분류**: 코드 없는 HTTP 502 검증 오류가 `TRANSIENT_FAILURE`로 분류되어 온도 0의 같은 전체 분석을 반복했다.
3. **구도별 생성 스키마 누락**: 실제 후속 원고가 relation·steps·comparison에 항목을 하나만 만들어 검수에서 실패했다. 근거 없는 항목을 채우는 대신 필요한 구도별 최소/정확 항목 수를 생성 스키마에 반영하고 다른 구도를 선택할 수 있게 했다.
4. **인쇄 필드와 제작 지시 혼동**: 실제 PNG의 condition에 색상·박스 배치 지시가, role에 내부 영문 코드가 출력됐다. 렌더러는 필드를 정상 출력했다. 파일 무결성과 초기 AI QA만으로는 발견하지 못했고 사람의 실제 PNG 검사로 확인했다.
5. **관찰과 기능 제약 혼동**: 첫 원문은 현재 PC에서 동작을 확인한 관찰이었다. 이를 PC 환경 의존성 또는 그 환경에서만 작동한다는 배타적 제약으로 바꾼 문구는 근거가 없었다.
6. **편집 QA 오탐**: 관찰 범위를 바로잡은 원고에 기존 QA가 제약 삭제와 의존성 추가라는 모순된 지적을 반환했고, 비인쇄 composition의 디자인 설명도 출력 조건으로 혼동했다. 검수 입력과 정책을 보정했다. QA를 강제로 통과시키지 않았다.

## 코드 수정

- `lib/source-evidence.ts`, `lib/analyze.ts`: 실제 원문의 연속 구절을 생성 evidence enum으로 제한하고 생성 후 원문 대조도 유지한다. 잘못된 문단 연결만 1회 부분 수정하며 기존 상세분석·유효 카드와 사용량 합산을 보존한다.
- `lib/local-ai.ts`, `lib/card-workflow.ts`: 형식 실패 `AI_RESPONSE_INVALID`, 근거 실패 `ANALYSIS_EVIDENCE_INVALID`를 연결 장애와 구분한다. 근거 복구 실패 후 같은 분석을 연결 재시도로 반복하지 않는다. 오류에 원문·프롬프트·응답을 넣지 않는다.
- `lib/card-workflow.ts`, `lib/card-pipeline.ts`: 로컬 생성에 정확한 장수·근거와 구도별 항목 수를 반영한다. relation/steps는 2개 이상, comparison은 정확히 2개이며 scene 등에는 항목을 억지로 요구하지 않는다.
- `lib/card-editor-prompt.ts`, `lib/card-presentation.ts`: 독자용 role/condition과 composition을 분리한다. 제작 지시·내부 코드가 잘못 들어간 필드만 1회 수정하고, 유효 조건·제목·본문·항목·근거·구도를 보존한다. 실제 원문 조건을 지워 통과시키지 않는다.
- `lib/card-editor-review.ts`: 원문 전체, 모든 인쇄 문구·항목·근거, 캡션과 한계를 QA에 유지한다. 비인쇄 composition/layout/direction·디자인 설정은 제외한다. 관찰 범위 메모와 실제 제약을 구분하고 구체적인 출력 문구와 원문 근거를 대조하도록 한다. 모델의 거절은 그대로 실패로 처리한다.
- `lib/card-revision.ts`, `lib/card-pipeline.ts`: 기존 run의 부분 편집에도 수정본 보존 경계를 적용한다. 검수 실패 시 내용을 보존해 waiting_input으로 돌리고 전체 원고 재생성으로 넘어가지 않는다.
- `tests/source-evidence.test.ts`, `tests/card-presentation.test.ts`: 실제 전송 스키마/프롬프트, 원문 인용·문단 연결·토큰 합산·오류 비공개화·조건 보존·관찰과 제약·QA 오탐 입력 경계·부분 수정 실패 보존을 회귀 검증한다.
